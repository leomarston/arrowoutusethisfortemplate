# Player world — data sources and licences

The name data the app's player world is built from is `App/Resources/Social/social_names.json`, built by
`design/social/tools/build_name_data.py` from the files below (the bundle's `Social/` folder also carries copies of those
source lists: `countries.tsv`, `given_*.txt`, `words_*.txt` and the block lists). Nothing is copied from the original game; no player
name, avatar or score of the original is reused (the original's names quoted in SPEC-social.md are evidence only and
are NOT in any list).

Rules that are built, not hand-picked (T6):
- **Invented-handle roots**: every 3-letter prefix shared by at least 3 Latin stems of `blocklist_substring_add.txt` (a conjugated
  family); a procedurally invented handle containing one is dropped from the pool (3 roots, 382 handles). This removes the
  audit's P1-4 example handles (social-intl §4) that the token-only rules alone let through: 0 of the 20 remain in the pool.
- **Published screen** (`tools/v2/pubscreen.py`): an LDNOOBW entry is used when it is one word of letters (>= 3 Latin letters,
  >= 2 characters in other scripts); a first name is dropped on whole-name / token equality, an invented handle also when a
  Latin entry of >= 5 letters occurs inside it. The name audit reports matches among shown names as a count.
- **Promotion**: a published entry that EQUALS one of our own generated tokens (a 2-3 letter initials run, an underscore or
  name+suffix suffix, an adjective / noun / word / caps token) joins the shipped token list — unless it is an ordinary English
  word (`/usr/share/dict/words`; a false friend such as a plain English suffix that is a mild word in one other language), which
  is reported apart. Result: 1 entry promoted (an initials run the audit found on 2 shown names), 1 English false friend kept.
  Long published entries INSIDE real first names (Scunthorpe cases) are reported by the audit, never used to drop real names.
- **Username rule for native forms**: outside Han, Hangul and kana a native-script name needs >= 3 characters (P2-4), so a
  2-letter Hebrew name is not in the list.
- **Native-script shares** (M6, ruling 38 = social-intl §7-2): ja 45 %, ko 50 %, zh 60 %, ar 30 %, ru / uk / bg 35 %, el 30 %,
  th 30 %, he 25 %; fa 30 % and kk 35 % (Arabic / Cyrillic, covered by those scripts' stems). **hy and ka: 0 %** — the lists
  carry no Armenian or Georgian stems, so those scripts are never shown (their Latin romanisations are).

Small-data exception: `hy` (Armenia, 204 names) and `ka` (Georgia, 257) hold every given name Wikidata records for those
countries' adults after screening, below the 300 of the other cultures (M7 shrinks the popularity head for short lists). Every
other culture used by a row has 300-600 names (`en` 2,478).

Nothing is copied from the original game or its players. Names are facts (not copyrightable); the Wikidata extracts are CC0.
No personal data is kept: only given-name items and counts (the persons' own ids appear only inside the Thai / Vietnamese label
extracts, which are public CC0 records and are not shipped). The shipped name resource carries one LDNOOBW-derived word (the
promotion above); the LDNOOBW lists themselves stay in `sources/` and are never shipped.
